## Context

审核已确认暂存区为空；部署配置和部分历史部署 change 已被 Git 跟踪，不能仅追加忽略规则。页面规划混有交付要求。发布、快照及其测试引用本机部署资料，需共同保留在本地，避免共享检出出现不存在的模块依赖。

## Goals / Non-Goals

**Goals:** 共享仓库包含应用、锁文件、静态字体许可、应用测试和产品规划；本地资料仍能维护、发布和回退。迁移可核验、不丢失原文。

**Non-Goals:** 不更改应用与部署算法，不更改服务器、不提交或推送、不重写历史、不自动归档。

## Decisions

- 忽略整个 deploy 目录、MAINTENANCE.md、TECH_STACK.md，以及两个本机辅助脚本和相应测试；这些文件留在原路径以保持现有工具引用和快照白名单可用。
- openspec-local 作为本地工作目录，其内部保留标准 openspec 子目录。通过切换工作目录使用 CLI，不注册全局 store、不改变 .agents 规划目标、不建立嵌套仓库。
- 五个部署／维护 change 整体移入本地规划；四个混合产品 change 先全文复制到本地 reference，再保留共享应用部分并生成本地交付／备份伴随 change。初始 linux-hosting 只留本地；FastAPI 服务要求归回应用规格。
- Git 索引仅移除明确枚举的本地路径与迁移旧路径；不批量添加其他未提交修改。.gitignore 保留原规则并增加根目录限定模式。
- 公共 README 只提供源码、内容、启动与应用测试方法；本地维护卡记录实际部署布局和 OpenSpec CLI 入口。已有本地发布包可重新构建，但冻结版本不变。

## Risks / Trade-offs

- [忽略但仍跟踪] → 逐项从索引移除并核对 git ls-files，磁盘哈希另行核对。
- [改写规划丢失原材料] → 本地 reference 完整保留原混合 change，整体移动核对相对文件清单与 SHA256。
- [共享检出依赖本地测试] → 发布和快照测试共同忽略，独立临时共享源码副本运行应用回归。
- [历史仍含路径] → 明确本轮只处理当前 Git 边界，旧历史保留；未获得重写授权。
