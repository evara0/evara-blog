## Why

用户已创建 GitHub 仓库并授权推送项目。当前源码已完成本地资料隔离，但旧 Git 提交仍包含已排除的环境资料，需在保留本地历史的同时发布经过审核的共享源码。

## What Changes

- 核对远程仓库为空及 Git 身份，复查共享候选、忽略边界与既有验证。
- 配置 origin 为用户指定仓库，精确暂存共享文件并保存本地源码快照。
- 从相同源码树创建无私有旧祖先的干净发布分支，常规推送至远程 main，保留本地原 main 历史。
- 验证远程提交、文件与可达历史；设置当前发布分支的上游和本仓库 push.default，便于后续更新。

## Capabilities

### New Capabilities

无。纯版本管理与交付操作，使用 skip_specs，不改变应用行为。

### Modified Capabilities

无。

## Impact

影响本地 Git 分支、索引、origin 与远程 main，以及本变更记录。实际部署、本机资料、备份、现有服务和原提交历史保持；不自动推送其他本地分支或标签，不强制推送。
