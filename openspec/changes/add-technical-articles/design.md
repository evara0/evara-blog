# Design

## Context

现有应用使用 FastAPI 提供静态页面和本地便签，签名在请求时读取。文章需与既有本地资料隔离并保持无构建步骤。

## Goals / Non-Goals

**Goals:** 以简单本地文件发布文章，安全呈现正文和图片，刷新即生效。

**Non-Goals:** 数据库、在线编辑、标签筛选、前端构建及部署。

## Decisions

- 使用 YAML safe loader 验证必填字段，日期为 ISO 日期，标签为字符串列表；可选 `draft` 必须为布尔值。草稿及未来文章包括资源均不公开。无效文章跳过并记录警告，避免一个文件阻断整个列表。
- 每次请求重新读取元信息；首页只解析元信息，详情使用 markdown-it-py 的 js-default 并关闭 HTML，Jinja2 自动转义普通字段。标题生成稳定且唯一的锚点与目录。
- 图片通过单独路由提供，仅允许常见安全栅格格式，解析后路径必须留在文章目录且拒绝符号链接，避免暴露 Markdown 和其他私人文件。相对图片 URL 重写为该路由；不开放整个目录的静态挂载。
- 实际文章默认忽略 Git，格式示例放在独立示例目录，避免误提交私人内容。
- 首页复用现有静态页面和导航，通过模板片段渲染最近八篇 Markdown 技术文章。`/blog` 复用同一列表片段，并保留来自 JSON 的文章目录、正文与锚点。JSON 条目没有发布日期，首页按 Markdown 文章的发布日期排序。
- Markdown 正文与资源使用 `/blog/<slug>` 和 `/blog/<slug>/assets/<path>`。`/articles` 及其正文继续使用原有文章转盘的目录数据。

## Risks / Trade-offs

- [每次扫描文件] → 当前规模无需缓存，新增或修改立即可见。
- [不支持 SVG] → 避免活动内容，仅支持常见栅格图片。
- [系统日期决定发布] → 文档说明使用服务器本地日期。

## Migration Plan

安装更新后的依赖，在文章目录添加内容即可；回退代码后原文章文件保留，原便签与个人页无需迁移。
